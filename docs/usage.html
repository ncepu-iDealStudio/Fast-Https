Fast-Https 使用文档

本文面向部署与运维人员，只讲"怎么装、怎么配、怎么跑、怎么排错"。开发、架构与测试相关内容在仓库 docs/ 下的其他目录，不随发行包分发。

文档中的路径都相对于解压后的程序根目录。配置里的相对路径按进程工作目录解析，因此请始终在根目录启动程序，或改用绝对路径。

2. 获取与安装

发行包

  1. 从 <https://gitee.com/ncepu-bj/fast-https/releases/> 下载对应平台的包
  2. 解压到目标目录（Linux/macOS 为 tar.gz，Windows 为 zip）
  3. 按需修改 config/fast-https.json

Linux 发行版包（deb / rpm / apk）

dpkg -i fast-https_*.deb                     # Debian / Ubuntu
rpm -ivh fast-https-*.rpm                    # RHEL / openEuler / CentOS
apk add --allow-untrusted fast-https_*.apk   # Alpine

包装好后的位置：程序 /usr/bin/fast-https，配置、站点与日志 /usr/share/fast-https/，服务单元 /usr/lib/systemd/system/fast-https.service，手册页 /usr/share/man/man1/fast-https.1。启动与查手册：

systemctl enable --now fast-https
man fast-https

首次安装时包里没有证书文件，先 systemctl start fast-https 生成自签证书，之后 fast-https check 才会通过。/usr/share/fast-https/ 下的目录归 root 所有，手工执行 start / check 要用 sudo，普通用户会因为写不了证书和日志而失败。运行期路径都以安装目录为基准，可以从任意工作目录执行 fast-https。

容器

docker build -f build/Dockerfile -t fast-https .
docker build -f build/docker/Dockerfile_ubuntu -t fast-https:ubuntu .
docker build -f build/docker/Dockerfile_centos7 -t fast-https:centos7 .

镜像基于 Alpine、Ubuntu 24.04 与 CentOS 7，暴露 8080 与 443。

3. 目录布局

fast-https                  主程序（Windows 下另有 monitor.exe 托盘程序）
config/fast-https.json      唯一配置真源
config/conf.d/              拆分出来的站点配置（由 http.include 指向）
config/mime.json            扩展名 → Content-Type 映射

httpdoc/root/               默认站点根目录
logs/                       运行日志

4. 快速开始

4.1 最小配置

config/fast-https.json：

{
  "log_root": "./logs",
  "http": {
    "server": [
      {
        "listen": 8080,
        "server_name": "localhost",
        "location": [
          {
            "url": "/",
            "type": "local",
            "root": "./httpdoc/root",
            "index": ["index.html", "index.htm"]
          }
        ]
      }
    ],
    "include": ["./config/conf.d"]
  }
}

4.2 启动并验证

./fast-https start                 # 无参数等同 start
curl -I http://127.0.0.1:8080/

看到 200 与 Server: fast-https 即启动成功。listen 也可以写成字符串 "8080"，两种写法等价。

4.3 打开 HTTPS 与 HTTP/2

{
  "listen": "443 ssl h2",
  "server_name": "localhost",
  "ssl_certificate": "./config/cert/localhost.pem",
  "ssl_certificate_key": "./config/cert/localhost-key.pem",
  "location": [
    { "url": "/", "type": "local", "root": "./httpdoc/root", "index": ["index.html"] }
  ]
}

ssl_certificate 指向的文件不存在时，启动阶段会用它自己签发的本地 CA 生成一张自签证书，可以直接用 curl -k 验证。浏览器不信任这张证书，正式环境请替换为权威 CA 签发的证书文件。

4.4 停止

./fast-https stop

Linux / macOS 上 stop 发送 SIGTERM，服务会关闭监听并等在途请求处理完（最长 GracefulStopTimeout）再退出，pid 文件随之删除；重复执行 stop 视为「本来就没在跑」，返回 0。Windows 上没有信号语义，直接终止进程。容器内、systemd（INVOCATION_ID）与设置了 FASTHTTPS_FOREGROUND=1 时 start 不转后台，交由进程管理器托管。

6. 典型配置

6.1 静态站点 + try_files

{
  "url": "/",
  "type": "local",
  "root": "./httpdoc/root",
  "index": ["index.html"],
  "try": [{ "uri": "/", "file": ["index.html"], "next": "" }]
}

6.2 反向代理

{
  "url": "/api/",
  "type": "proxy",
  "proxy_pass": "http://127.0.0.1:9000",
  "proxy_set_header": [
    { "HeaderKey": "X-Real-IP", "HeaderValue": "$remote_addr" },
    { "HeaderKey": "X-Forwarded-For", "HeaderValue": "$proxy_add_x_forwarded_for" }
  ]
}

proxy_pass 缺少 http:// / https:// 前缀时会按 local 处理，不会报错，这是最容易踩的坑。

6.3 TCP 转发

{
  "listen": "9000 tcp",
  "server_name": "db",
  "location": [{ "url": "/", "type": "proxy", "proxy_pass": "http://10.0.0.9:3306" }]
}

listen 带 tcp 时整条连接按四层转发，不解析 HTTP。

6.4 压缩

{ "url": "/", "type": "local", "root": "./httpdoc/root", "zip": ["gzip", "br"] }

按 Accept-Encoding 协商，客户端同时支持时优先给 brotli。

6.5 代理缓存

"proxy_cache": {
  "path": "./cache",
  "key": "$request_uri",
  "valid": ["200:1h", "404:1m", "any:5m"],
  "methods": ["GET", "HEAD"],
  "max_size": 1073741824
}

valid 的格式是 状态码:时长，any 匹配其余状态码；命中会顺延一个周期（读即续期）。key 支持变量插值。

6.6 Basic 认证与限流

{
  "url": "/admin/",
  "type": "local",
  "root": "./httpdoc/admin",
  "auth": { "type": "basic", "user": "admin", "pswd": "change-me" },
  "limit": { "rate": 10, "burst": 20, "nodelay": true }
}

7. TLS 与证书

  • SNI 多证书：同一端口上的多个 server_name 各自持有证书，握手时按 SNI 选择，匹配不到用该端口的第一张。
  • 自动生成：首次启动时，若 config/cert/<server_name>.pem 不存在，会用一个本地自签 CA 生成证书。CA 有效期 10 年，域名证书 2 年 3 个月。
  • 热替换：执行 reload 后证书从磁盘重新加载，不需要重启进程。
  • 不自动续期：程序只判断文件是否存在，不检查有效期。证书过期前需要替换文件并 reload。
  • 外部签发：用 acme.sh、certbot 等外部工具签发后，把 fullchain.pem 与私钥路径填进 ssl_certificate / ssl_certificate_key 即可。

本地 CA 的证书 root.crt 放在 httpdoc/root/（首页可直接下载安装），私钥 root.key 放在 config/cert/，不在对外服务的站点根下。旧版本把两者都放在站点根，升级后首次启动会把私钥搬到 config/cert/。如果你自己改过站点根，确认新目录里不含私钥。

8. HTTP/2

listen 加上 h2 即可，例如 "listen": "443 ssl h2"。

  • ALPN 只在含 h2 的端口通告 h2，纯 ssl 端口只走 HTTP/1.1，避免浏览器协商到 HTTP/2 后被 HTTP/1.1 解析器处理。
  • 同一端口同时通告了 http/1.1，不支持 HTTP/2 的客户端会自动降级。
  • reload 或停止时通过 http.Server.Shutdown 发送 GOAWAY 并等待在途请求，最长 5 秒。

9. 日志

运行日志都写成 JSON，位于 log_root 指向的目录：

文件内容
system.log启动、配置加载、监听建立等系统事件
access.log访问日志，字段由 log_format 决定
error.log运行时错误
safe.log黑名单、限流、应用防火墙命中

log_format 可按任意顺序组合以下字段：

字段含义
ip_port客户端地址与端口
time请求时间
type命中的 location 类型
method请求方法
path请求路径
host请求的 Host
status响应状态码
size响应字节数
user_agentUser-Agent

修改 log_root 后执行 reload 会重新打开日志文件；新目录打不开时继续写原文件。

10. 命令行

命令作用
start以守护进程方式启动（无参数等同此命令）
dev前台启动，日志级别 6，并在 0.0.0.0:10000 开 pprof
stop停止服务
reload校验配置后热重载，失败时保留旧配置
status读 pid 文件，进程存在返回 0，否则非 0
check只校验配置，不监听端口、不写 pid
install安装为系统服务
uninstall卸载系统服务

两点行为需要留意：

  • dev 模式下 Ctrl+C 是停止服务，不是重载。
  • check 通过时打印 config ok 并以 0 退出；start 的预检会做同一项校验。

11. 热重载与停机

reload 的流程是：解析并校验新配置 → 校验失败则继续用旧快照 → 校验通过则原子替换快照 → 按差异增删改监听器 → 重新打开证书表与日志文件。整个过程中已有连接不受影响。

守护进程模式下的等价操作是向主进程发送 SIGINT。停止时先停止接受新连接，再等待在途请求完成。

12. 排错

现象原因与处理
启动报 ssl_certificate not foundlisten 含 ssl 时证书文件必须存在。首次启动会自动生成 config/cert/<server_name>.pem，请确认路径与 server_name 一致，或改用绝对路径
启动报 listen: port already in use端口被占用，换端口或先释放
配置校验通过但访问 404检查 root 是相对路径时的实际解析位置，确认 server_name 与请求 Host 一致
反向代理返回 404 或落到静态分支proxy_pass 缺少 http:// / https:// 前缀，被当作 local 处理
HTTP/2 不生效listen 没写 h2；或客户端不支持 ALPN。可用 curl -I --http2 https://... 验证协议版本
修改配置后不生效守护进程模式需要执行 reload；dev 模式需要重启
日志没有写到新目录新 log_root 打不开时程序继续写原文件，检查目录权限

13. 已知限制

项说明
ACME 自动签发未接入。仓库内的 acme.sh 不参与启动流程，证书需外部工具签发后填入路径
证书自动续期不支持，需人工替换后 reload
engine 配置段主从注册的预留字段，当前不参与运行逻辑
上游故障转移未实现，单个上游不可用时直接返回错误页
配置文件自动重载暂不支持，监听文件变化后自动 reload 仍未排期
