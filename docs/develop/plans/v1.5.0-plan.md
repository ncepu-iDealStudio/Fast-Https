### 阶段 1：ACME 证书自动化

以 [acme-certmagic-plan.md](acme-certmagic-plan.md) 为基线，本阶段追加三项原方案没有的内容。

**1.1 依赖与配置**

- 引入 `github.com/caddyserver/certmagic`（注意模块路径不是 `mholt/certmagic`，见原方案第 2 节记录）。
- 顶层 `acme` 段：`enabled`、`email`、`staging`、`challenge`、`renew_before_days`、`fallback_self_signed`、`storage`、`cas`。
- 校验：`challenge` 只接受 `auto` / `http-01` / `tls-alpn-01`；显式写了 `http-01` 但没有任何 80 监听时 `check` 给警告。`auto` 不告警，可用性交给运行时探测。

**1.2 CA 降级链**

- `cas` 是有序数组，每项 `{ "name", "directory", "eab_kid", "eab_hmac_key" }`。默认顺序：Let's Encrypt → ZeroSSL，最后隐式回落本地自签。
- certmagic 的 `Config.CA` 是单值，因此每个 CA 建一个 `certmagic.Config` 实例，共享 `FileStorage`，账户按 `<storage>/<ca-name>/` 分目录。
- 签发：按 `cas` 顺序调 `ObtainCertSync`，首个成功即停，把 `域名 → CA 名` 写入 `acme/state.json`。
- 续期：`ManageAsync` 只挂在成功签发那个 CA 的实例上；该 CA 续期失败时重新走一次降级链并更新 state。
- ZeroSSL 必须 EAB：`eab_kid`/`eab_hmac_key` 为空时跳过该 CA 并告警，不做匿名注册尝试。EAB 通过 `certmagic.ACMEIssuer` 的 ExternalAccount 传入，字段名以引入版本为准。

**1.3 staging 验证**

- `acme.staging: true` 时把 Let's Encrypt 目录替换为 staging 端点，并在启动日志与 `check` 输出显著告警"证书不受信任"。
- 联调用独立 `storage`（如 `config/cert/acme-staging/`），避免 staging 证书进入生产 PEM。

**1.4 挑战自动化与热替换**

目标是"用户不需要知道挑战是什么"。挑战应答全部由进程自己完成：

- 应答挂载：HTTP-01 的 token 由 `core.Services.HandleEarlyRequest` 在路由之前响应；TLS-ALPN-01 的临时证书注入 `listener` 的 ALPN 表。不写站点目录、不改配置文件、不开额外端口。
- 能力探测：签发前读取当前配置判断可用性——没有 80 监听则 HTTP-01 不可用，没有 ssl 监听则 TLS-ALPN-01 不可用。
- 自动排序：`challenge` 默认 `["auto"]`，按探测结果排序，默认 TLS-ALPN-01 优先（不依赖 80 端口）；探测不到任何可用挑战时直接回落自签并告警。
- 自动切换：某个挑战被 CA 拒绝（超时、404、证书校验失败）时，在同一次签发流程内换下一个挑战重试，不需要用户再执行一遍命令。
- 自动清理：`CleanUp` 在挑战结束（无论成功或失败）后移除 token 与临时证书；进程重启后两张表为空。
- 失败原因落日志：按域名记录尝试过的挑战、CA 返回的错误类别、最终使用的 CA，不打印密钥与完整证书链。
- 热替换：PEM 写回后调用 `listener.ReloadCerts`，监听端口不中断。

边界：程序只能保证"本地应答全自动"。公网 80/443 是否可达、DNS 是否指向本机、端口是否被其他进程占用，都不在程序控制内；探测失败时按上述规则跳过或回落，并在日志与 `cert status` 中给出可读原因，不静默失败。

**1.5 `cert` 命令组与交互初始化**

证书配置不要求用户手写 JSON。新增 `cert` 命令组，交互层复用 2.4：

| 命令 | 行为 |
| --- | --- |
| `cert init` | 交互向导：是否启用 ACME、账户邮箱、CA 顺序（含 ZeroSSL EAB）、挑战方式（自动 / 仅 HTTP-01 / 仅 TLS-ALPN-01，默认自动）、是否 staging；写回主配置的 `acme` 段，结束提示 `check` → `reload` |
| `cert status` | 列出每个域名的证书来源（acme / 自签 / 手工）、到期时间、下次续期时间、当前使用的 CA |
| `cert renew [domain]` | 手动触发一次签发或续期，省略域名时处理全部 |
| `cert show` | 打印生效的 `acme` 配置，EAB 私钥脱敏 |

向导与参数两种入口并存：`cert init --email a@b.c --ca letsencrypt,zerossl --yes` 可完全跳过提问，供脚本与 CI 使用。

**验收**

- 单元测试：token 表写读清、挑战路径 200/404、降级链（假 CA 客户端：前两个失败、第三个成功）、EAB 缺失时跳过 ZeroSSL。
- 挑战自动化：`auto` 模式在没有 80 监听时只用 TLS-ALPN-01；人为让 HTTP-01 失败后自动切到 TLS-ALPN-01，并在同一次流程内签发成功。
- 挑战清理：成功、失败、进程中断三条路径结束后，token 表与 ALPN 表都为空。
- `cert init` 向导与参数模式生成同一份配置（逐字节一致）；`cert show` 不输出 EAB 私钥。
- staging 冒烟：`acme.staging=true` 下对真实域名签出一张 staging 证书并热替换成功，日志无密钥与完整链输出。
- 失败回落：断网或错误目录时服务仍以自签启动，日志只告警，按指数退避重试不刷屏。

### 阶段 2：`site` 命令组与交互向导层

**2.1 命令注册扩展**

`cmd` 现在的 `command` 结构只有 `handler func() error`，无法承载子命令与参数。改为：

```go
type command struct {
    name        string
    description string
    handler     func(args []string) error        // 现有命令忽略 args
    register    func(parent *cobra.Command)      // 需要嵌套子命令时使用，如 site
}
```

`RootCmd` 保持现有扁平命令行为不变，仅对 `register != nil` 的命令走自定义注册。

**2.2 站点模型与合并**

- 业务逻辑放 `modules/site`，cmd 只做参数解析与输出格式化。
- 站点文件：`conf.d/<name>.json`，内容与 `http.server[]` 元素同构，直接复用 `config.jsonServer` 的字段名，保证 2.0 可直接读取。
- 目录来源：取 `config.Current().Include` 首项；未配置 include 时 `site` 子命令直接报错并提示先在主配置写 `http.include`。
- 合并与校验必须复用 `config.LoadFile` / `config.ValidateConfigFile`，不得另写一套合并逻辑。

**2.3 子命令**

| 命令 | 行为 |
| --- | --- |
| `site init [name]` | 交互向导：站点名、监听端口、`server_name`、站点类型（静态 / 反代 / TCP）、根目录或上游地址、是否启用 TLS。参数齐全或加 `--yes` 时跳过提问，只生成文件 |
| `site list` | 扫描 include 目录，输出名称、文件、监听、`server_name`、location 类型摘要 |
| `site check [name]` | 复用 `ValidateConfigFile`；给定 name 时额外报告该文件在合并冲突中的位置 |
| `site show <name>` | 打印**生效快照**（合并 `http.server` 与 include 之后该 server 的实际 JSON），并标注来源文件 |
| `site remove <name>` | 删除文件，要求 `--yes`，删除后只提示执行 `reload`，不自动重载 |

**2.4 交互向导层（`cert` 与 `site` 共用）**

- 抽象 `Prompter` 接口（提问 / 确认 / 单选），默认实现基于 `bufio` 读写 stdin 与 stdout，不引入 TUI 依赖，避免为了几个问题增加整包体积。
- 非 TTY 检测：stdin 不是终端（管道、CI、systemd）时直接报错并提示改用参数模式，不能挂起等待输入。
- 可测试性：向导只依赖 `Prompter`，测试注入脚本化答案序列，断言生成的 JSON；用例覆盖"全部取默认值""参数齐全跳过提问""EOF / Ctrl+C 中途放弃""目标文件已存在拒绝覆盖"。
- 写入安全：先写 `.tmp` 再 `rename`；EAB hmac key 等敏感项输入不回显；生成后立即跑 `config.ValidateConfigFile`，失败时报字段路径且不覆盖原文件。
- 只写配置不重启：结束时打印生成的文件路径、配置摘要与后续命令（`fast-https check` → `fast-https reload`），由用户决定何时生效。
- **改写主配置必须保留注释**：`infra/jsonc` 允许 `//`、`/* */` 与尾随逗号，主配置本身是带注释的示例文件。`cert init` 不能用"反序列化再整体序列化"的方式回写（会丢注释与键顺序），要定位 `"acme"` 对象区间做文本替换，并在写入后用 `config.ValidateConfigFile` 复核。`site init` 新建的是全新文件，不受此限。

**验收**

- `site show` 输出与数据面加载结果一致：用同一份配置分别走 `site show` 与 `config.LoadFile`，逐字段比对。
- 非法站点文件在 `site check` 中报出文件路径与字段路径。
- `site init` 产物能被 `config.ValidateConfigFile` 直接通过。
- 向导与参数模式产出的文件逐字节一致；非 TTY 下报错退出；中途放弃不留半截文件。
- `modules/site` 与 `modules/certmanager` 不 import `runtime/*`、`cmd`，由 `tests/arch` 守卫覆盖。

> 实施记录（2026-11-02，试用反馈）：最初的 `site init --tls` 会在默认 `listen` 80 上追加
> `ssl h2`，得到 `"80 ssl h2"` —— 既不是 HTTP 也不是 HTTPS，而且 HTTPS 站点本该监听 443。
> 同一次反馈暴露了两个缺口，一并修掉：
>
> 1. **多监听**：`listen` 升级成 `flexList`（`"listen": ["80", "443 ssl h2"]`），加载时展开成多个
>    运行期 server 块，`server_name`/location/证书共用；`--listen` 改为可重复。`--tls` 语义改为
>    「至少一个 TLS 监听，且绝不把 ssl 贴到 80 上」。
> 2. **反代被静态抢走**：`matchLocation` 原来是"按配置顺序第一个命中"，`location /`（静态）
>    会把 `/api`（反代）永远挡住；改成 nginx 前缀语义（起点命中优先 → 匹配更长优先 → 同长保序）。
>    同时修掉 Host 归一化：HostMap 键是 `server_name:port`，非标准端口上客户端不带端口，
>    曾导致请求落到 `default_server`（表现为"配了反代却进了别的站点"）。
>
> 站点名带 `.json` 也一并容错（不再生成 `a.json.json`）。

### 阶段 3：安全加固收尾

**3.1 URI 规范化**（`runtime/request` 或 `runtime/filters`）

- 合并连续 `/`、解码一层 `%xx`、拒绝含二次编码（`%252f`）、反斜杠、控制字符、超长（`> 8192`）的 URI，拒绝时 400。
- 规范化结果写回请求路径，location 匹配、静态文件解析、日志统一使用规范化后的值；查询串不参与规范化。
- 必须保持现有 `staticPathInRoot` 的穿越防护语义不变。

**3.2 Host 校验**

- 新增 `security.host_check`：`off`（默认）/ `warn` / `enforce`。
- `enforce` 时 Host 不匹配任何 `server_name` 返回 421，且不落到默认 server；`warn` 只写安全日志。
- 默认 `off` 保持现有"回落默认 server"行为，避免破坏用 IP 或别名访问的现网。

**3.3 方法限制**

- location 新增 `allow_methods`（空 = 不限制，兼容现状）；不在列表内返回 405 并带 `Allow` 头。
- `HEAD` 与 `GET` 的既有语义保持（`HEAD` 不写正文）。

**3.4 安全响应头**

- 新增 `security.headers`，在 `runtime/response` 统一出口写入，避免各模块各写一遍。
- 默认只开 `X-Content-Type-Options: nosniff`（无兼容风险）；`Strict-Transport-Security`、`X-Frame-Options`、`Referrer-Policy`、`Content-Security-Policy` 需显式开启。
- `Server` 头保持现状。

**验收**：URI 规范化表驱动用例（含 `//`、`%2f`、`%252f`、反斜杠、超长）；Host 三态行为；`allow_methods` 405 与 `Allow`；响应头存在性与默认值；`-race` 全绿。

### 阶段 5：性能基线

## 6. 风险与开放问题

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| ZeroSSL 需要 EAB | 无 EAB 无法注册账户，清单未提 | 配置项显式提供，缺失时跳过并告警；文档写明获取方式 |
| Host 校验改变路由 | `enforce` 会让 IP/别名访问 421 | 默认 `off`，仅显式开启 |
| 安全响应头影响现网 | HSTS 误开会锁死 HTTP 站点 | 默认只开 `nosniff`，其余显式开启 |
| 删除 install | 老用户升级后命令消失 | usage 给迁移说明，保留一个版本期的提示日志 |
| certmagic 体积 | 可能链入 lego | 阶段 1 结束即测体积，超标再裁剪 |
| PGO 文件 | 给仓库与构建加负担 | 只在收益达标时引入 |
| `site` 与 2.0 | 站点模型若与 2.0 设计不一致会返工 | 字段直接复用 `jsonServer`，2.0 只做读取方 |
| 向导与手改冲突 | 向导写主配置，用户可能同时手改同一文件 | 写入前比对内容指纹，已变化则中止并提示；只改 `acme` 段或新建 `conf.d/*.json`，不动无关字段 |
| 挑战自动化的边界 | 本地应答能全自动，公网 80/443 可达性、DNS 解析、端口被占用都不由程序控制 | 探测失败时跳过该挑战并回落自签，`cert status` 与日志给出可读原因，不静默失败 |

开放问题：

- `site remove` 是否需要软删除（移动到 `conf.d/.trash/`）而不是直接删。
- `security.host_check` 的 `warn` 日志是否要限频。
- ACME 账户邮箱变更时是否复用旧账户（建议复用，仅记录变更）。
