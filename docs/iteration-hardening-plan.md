# Fast-https 开发迭代加护计划（技术债分级）

## 1. 文档目标
本计划用于指导 fast-https 在后续迭代中，优先处理会影响稳定性、可运维性、可测试性的技术债。

输出重点：
- 明确当前问题与技术债
- 说明如果不处理，未来可能导致的风险
- 给出分级治理路径与验收标准

## 2. 分级标准
- P0（阻断级）: 影响核心稳定性、发布可靠性或线上可恢复能力；必须优先处理
- P1（高优先级）: 当前可运行但有明显事故隐患或持续拖慢开发效率；应在近期迭代完成
- P2（中优先级）: 质量与可维护性问题，短期不阻断上线，但会放大后续成本
- P3（优化级）: 体验、性能细节或工程一致性改进，可在专项窗口处理

## 2.1 难易度定义（用于排期）
- 易: 改动点集中、依赖少、可在 0.5-2 天内完成并验证
- 中: 跨 2-4 个模块，需要回归验证，通常 2-5 天
- 难: 涉及架构或协议行为调整，跨平台/跨协议验证复杂，通常 1-3 周

## 3. 问题清单与未来风险

### 3.1 P0（阻断级）

#### P0-1 配置校验缺失
- 当前表现:
  - 配置预检流程调用了校验，但校验函数实际为空实现（config.CheckConfig 返回 nil）
  - 关联位置: config/config.go
- 如果不处理的未来问题:
  - 错误配置在启动阶段无法被阻断，可能在运行期触发崩溃或行为异常
  - 线上变更难以做到“发布前失败”，会增加故障窗口和回滚压力
- 优化动作:
  - 建立结构化配置校验器（必填项、端口格式、证书路径、location 合法性、类型枚举）
  - 校验失败时输出可读错误并阻断启动
  - 为 include 子配置建立统一校验入口
- 验收标准:
  - 覆盖常见坏配置的单元测试
  - 启动前可明确报出错误字段和错误原因

#### P0-2 测试基线不可用（主干无法稳定通过）
- 当前表现:
  - 全量测试失败，存在多类失败源
  - hpack 包 init 中执行 flag.Parse，与 go test 参数冲突
  - 部分测试依赖外部环境（证书文件）导致 panic
  - 部分测试与当前实现偏离
- 如果不处理的未来问题:
  - 无法建立可靠 CI 门禁，回归风险持续累积
  - 每次迭代都可能引入隐性缺陷，发布质量不可预测
- 优化动作:
  - 移除库级 init 中不必要的 flag.Parse
  - 将文件依赖改为测试夹具或临时文件
  - 修复与当前实现脱节的断言，恢复“可执行且可信”的测试集
  - 按包建立最小可行测试门槛（先确保关键路径）
- 验收标准:
  - go test ./... 在标准开发环境下可稳定通过
  - CI 固化自动测试并提供失败定位信息

#### P0-3 Reload 能力不完整（跨平台与协议）
- 阶段进展（2026-06-23，阶段 1）:
  - 已增加跨平台 reload 触发抽象：Windows 优先 Ctrl+C 事件，其他平台使用 SIGINT
  - 已补充 HTTP/2 在 listener context cancel 时的连接退出路径
  - 已增强 HTTP/2 连接关闭幂等性，避免重复关闭引发异常
  - 已新增对应单测并通过全量回归
- 阶段进展（2026-06-23，阶段 2）:
  - reload 时已主动关闭被移除端口的旧 listener（cancel + close）
  - 被移除端口会输出明确日志，便于排障和审计
  - 阶段改造后已通过全量回归测试
- 阶段进展（2026-06-23，阶段 3）:
  - 已新增 reload 端口切换端到端回归测试资产（test/client_test/reload_e2e_test.go）
  - 测试默认跳过，不影响日常 `go test ./...`，可通过环境变量按需启用
  - 已补充测试执行文档，便于发布前做专项回归
- 当前表现:
  - Windows reload 分支仍是 TODO
  - HTTP/2 reload 有明确未完成标记
- 如果不处理的未来问题:
  - 配置变更需要重启服务，导致连接中断和可用性下降
  - 多平台行为不一致，运维流程复杂且容易误操作
- 优化动作:
  - 统一 reload 协议，明确 Linux/Windows 的信号与控制通道
  - 补齐 HTTP/2 连接与监听器重载策略
  - 增加 reload 集成测试（新增端口、删除端口、证书更新、配置错误回滚）
- 验收标准:
  - Linux 与 Windows 重载行为一致且可验证
  - HTTP/1.1 与 HTTP/2 均通过重载回归测试

### 3.2 P1（高优先级）

#### P1-1 监听与连接生命周期治理不足
- 当前表现:
  - 监听器重载与连接处理存在多处 TODO，部分流程边界不清晰
- 如果不处理的未来问题:
  - 长连接或高并发下可能出现资源泄漏、连接悬挂、重复关闭等问题
  - 故障排查困难，恢复时间拉长
- 优化动作:
  - 明确 listener、event、ctx 的生命周期状态机
  - 为超时、关闭、重载切换建立统一退出路径
  - 在关键路径增加轻量指标与结构化日志
- 验收标准:
  - 压测场景下连接数、goroutine、fd 曲线稳定
  - 重载和关停流程无异常增长或阻塞

#### P1-2 模块注册与可插拔机制一致性不足
- 当前表现:
  - 模块注册依赖 side-effect import，部分模块注册代码实际被注释
- 如果不处理的未来问题:
  - 新增模块易出现“编译通过但运行缺模块”的问题
  - 测试和生产行为可能不一致
- 优化动作:
  - 固化模块注册规范（显式注册 or 统一引导注册）
  - 启动时输出模块注册清单与缺失检测
  - 为模块注册建立健康检查测试
- 验收标准:
  - 缺失模块可在启动前被识别并阻断
  - 模块单测可独立运行且结果稳定

#### P1-3 配置与样例文档不一致
- 当前表现:
  - dev.yaml 与主配置路径使用的 json 体系并不一致
- 如果不处理的未来问题:
  - 开发者按文档配置后启动失败，增加入门门槛
  - 测试环境与生产环境配置模式偏移
- 优化动作:
  - 明确“唯一配置真源”与多环境覆盖策略
  - 同步 README 与配置样例，避免双轨语义
- 验收标准:
  - 新开发者可按文档完成首次启动
  - 开发/测试/生产配置格式和加载顺序可追踪

### 3.3 P2（中优先级）

#### P2-1 日志系统输出语义和测试期望不一致
- 当前表现:
  - 日志输出流（stdout/stderr）和测试断言不匹配，已有 TODO
- 如果不处理的未来问题:
  - 监控采集与告警规则容易误判
  - 日志测试长期不稳定，干扰问题定位
- 优化动作:
  - 统一日志级别到输出流映射规则
  - 规范日志格式，保证可检索性
- 验收标准:
  - 日志相关单测稳定通过
  - 运行日志可直接用于故障检索和审计

#### P2-2 HTTP/2 与 HPACK 代码的可维护性债务
- 当前表现:
  - HPACK/HTTP2 子模块内存在多处 TODO/FIXME
- 如果不处理的未来问题:
  - 协议边界场景下可能出现兼容性问题
  - 后续修复成本呈指数上升
- 优化动作:
  - 梳理协议错误分支和边界行为
  - 增加协议层回归测试和示例
- 验收标准:
  - 关键协议分支有测试覆盖
  - reload 与连接异常场景行为可预期

#### P2-3 安全与限流策略的验证不足
- 当前表现:
  - 安全、限流、应用防火墙相关路径存在测试缺口
- 如果不处理的未来问题:
  - 流量尖峰和恶意请求下稳定性与安全性不可控
- 优化动作:
  - 建立安全回归测试（XSS、SQL 注入、限流触发、黑名单）
  - 对关键策略引入可观测指标
- 验收标准:
  - 防护策略可通过自动化测试验证
  - 安全策略变更可量化评估效果

### 3.4 P3（优化级）

#### P3-1 配置热监控能力未落地
- 当前表现:
  - watchConfigChanges 仍为空逻辑
- 如果不处理的未来问题:
  - 动态配置能力受限，变更操作依赖人工流程
- 优化动作:
  - 引入文件变更监听与防抖机制
  - 与 reload 管线联动并支持失败回滚
- 验收标准:
  - 配置变更可自动触发安全重载

#### P3-2 代理 upstream 能力扩展准备不足
- 当前表现:
  - proxy upstream 逻辑有预留 TODO
- 如果不处理的未来问题:
  - 复杂代理场景支持能力不足
- 优化动作:
  - 设计 upstream 抽象（健康检查、负载策略、故障转移）
- 验收标准:
  - upstream 能力可在不破坏现有配置下渐进引入

## 5. 里程碑验收指标
- 可靠性:
  - 启停与重载成功率
  - 异常退出率
- 质量:
  - go test ./... 通过率
  - 核心路径测试覆盖率
- 可运维性:
  - 配置错误发现前置率
  - 故障定位平均时长

## 6. 执行原则
- 先止血再优化，先 P0 后 P1
- 简单问题优先: 同等级下优先处理“易 + 高收益 + 可快速验证”的项
- 每项治理必须有自动化验证
- 所有改造保持向后兼容，避免一次性大爆炸重构
- 文档与代码同迭代更新，防止再次偏离
